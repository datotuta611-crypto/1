# Задание: песочница Claude Code на этом VPS

## Цель

Пользователь будет работать с Claude Code на этом сервере двумя способами:

- **из панели VS Code** через Remote-SSH и Dev Containers, подтверждая каждую правку по диффу;
- **из терминала** командой `claude-box <папка проекта>`.

В обоих случаях Claude работает в Docker-контейнере от обычного пользователя, видит только один проект и входит по подписке Claude, без API-ключа. По умолчанию включён режим Manual: правки файлов показываются диффом и ждут подтверждения.

Всё устанавливает скрипт `setup-claude-box.sh` из этой же папки. Не переписывай его и не собирай схему вручную.

## Шаги

1. **Проверь окружение:** `cat /etc/os-release`, `id`, `docker compose version`.
   Если нет Docker или compose v2, установи Docker Engine и `docker-compose-plugin` из официального репозитория Docker по инструкции для этой ОС: https://docs.docker.com/engine/install/. Через snap не ставь.

2. **Спроси пользователя**, если ещё не знаешь:
   - имя и почту для git-коммитов (можно пропустить);
   - где лежат проекты;
   - его **публичный** SSH-ключ для входа под `dev` (нужен для Remote-SSH) или разрешение скопировать для `dev` ключи из `/root/.ssh/authorized_keys`.

3. **Запусти скрипт.**
   - Под root: `CB_USER=dev GIT_NAME="…" GIT_EMAIL="…" bash setup-claude-box.sh`
   - Под обычным пользователем с доступом к Docker: то же самое без `CB_USER`.

   Скрипт завершается только с тремя кодами:
   - **0** — готово, в конце строки `[setup] ИТОГ`;
   - **1** — ошибка, причина в строке `[setup] ОШИБКА`; устрани её и запусти снова, повторный запуск безопасен;
   - **2** — нет Docker или docker compose v2.

   Если ошибка возникла при загрузке образа с Docker Hub (`429 Too Many Requests`), подожди минуту и повтори.

4. **Настрой SSH для `dev`** только тем ключом, который дал пользователь:
   ```bash
   install -d -m 700 -o dev -g dev /home/dev/.ssh
   # добавь ключ в /home/dev/.ssh/authorized_keys
   chown dev:dev /home/dev/.ssh/authorized_keys && chmod 600 /home/dev/.ssh/authorized_keys
   ```
   Не меняй `sshd_config`, не включай вход по паролю, не создавай ключи за пользователя.

5. **Проверь каждый проект.** Под root:
   ```bash
   runuser -u dev -- /home/dev/.local/bin/claude-box /путь/к/проекту --version </dev/null
   ```
   Под обычным пользователем команда та же, только без `runuser -u dev --`. Должна вывестись версия Claude Code. Папку указывать обязательно: `claude-box` без папки не запускается.

   Если вместо версии пришло `принадлежит другому пользователю` или `не найдена или к ней нет доступа`, **остановись и спроси пользователя**. Предложи перенести проект в `/home/dev/projects/` и/или выполнить `chown -R dev:dev` на эту папку, назвав точные пути. Делай это только после явного согласия.

   Если пришло `похожа на папку с несколькими проектами`, это папка-контейнер, а не проект. Проверяй каждый проект внутри неё по отдельности. Флаг `CLAUDE_BOX_ALLOW_PARENT=1` используй, только если пользователь прямо подтвердил, что это один проект.

6. **Подготовь проекты для VS Code.** Для каждого проекта, с которым пользователь будет работать из панели:
   ```bash
   runuser -u dev -- /home/dev/.local/bin/claude-box --vscode /путь/к/проекту
   ```
   Команда создаёт в проекте `.devcontainer/claude-box/devcontainer.json` и, если проект — git-репозиторий, добавляет эту папку в `.git/info/exclude`, чтобы она не попала в коммиты. Чужой `.devcontainer/devcontainer.json` проекта она не трогает.

7. **Вход по подписке выполняется только вместе с пользователем.** Вход общий для терминала и VS Code.

   Варианты в порядке предпочтения:
   - Пользователь входит в панели Claude Code в VS Code: кнопка **Sign in**, браузер откроется на его компьютере.
   - Пользователь заходит по SSH под `dev` и выполняет `claude-box /путь/к/проекту auth login`.
   - Если оба варианта ему недоступны, проведи вход через tmux (установи `tmux`, если его нет):
     ```bash
     runuser -u dev -- tmux new-session -d -s cblogin -x 400 -y 50 \
       "/home/dev/.local/bin/claude-box /путь/к/проекту auth login"
     runuser -u dev -- tmux set-option -t cblogin remain-on-exit on
     sleep 10
     runuser -u dev -- tmux capture-pane -p -J -t cblogin | grep -o 'https://claude.ai/oauth/authorize[^[:space:]]*'
     ```
     Отправь пользователю ссылку целиком и попроси прислать код, который он увидит после входа. Ссылка привязана к этому процессу: пока ждёшь код, не перезапускай сессию, иначе код не подойдёт. Получив код:
     ```bash
     runuser -u dev -- tmux send-keys -t cblogin -l 'КОД'
     runuser -u dev -- tmux send-keys -t cblogin Enter
     sleep 8; runuser -u dev -- tmux capture-pane -p -J -t cblogin | tail -5
     runuser -u dev -- tmux kill-session -t cblogin
     ```
     Не сохраняй код ни в файлах, ни в логах.

   Проверка: повторно запусти `setup-claude-box.sh`. Строка `[setup] ИТОГ: вход:` должна сказать `выполнен (подписка Claude)`. Любой другой способ входа (`api_key`, `api_key_helper` и т. п.) — повод остановиться и сообщить пользователю.

8. **Отчитайся пользователю:**
   - строки `[setup] ИТОГ` (включая предупреждение про группу docker);
   - список проектов с результатом проверки и признаком «подготовлен для VS Code»;
   - статус входа.

   Передай ему раздел «Как пользоваться».

## Запрещено

- Создавать, запрашивать или прописывать `ANTHROPIC_API_KEY`, `apiKeyHelper` и любые другие ключи: они перекрывают подписку.
- Запускать контейнер от root и монтировать в него `/`, `/root`, домашнюю папку или папку со всеми проектами сразу.
- Без явного согласия пользователя переносить или удалять проекты, менять их владельца или права, использовать `CLAUDE_BOX_ALLOW_PARENT=1`.
- Создавать `docker-compose.override.yml`, менять режим разрешений Claude (`permissions.defaultMode`) или включать `--dangerously-skip-permissions`.
- Менять настройки Docker-демона, `sshd_config`, сети, файрвола, открывать порты.
- Править `setup-claude-box.sh` или файлы, которые он создаёт. Если скрипт падает по причине, которую нельзя устранить в системе, остановись и опиши ошибку пользователю.

## Как пользоваться (передай пользователю)

**Важно о безопасности.** Пользователь `dev` состоит в группе `docker`, а это права уровня root на сервере. Не давайте доступ к `dev` тем, кому не дали бы root. Сам Claude в контейнере работает без этих прав: Docker-сокета у него нет.

**VS Code: панель с подтверждением диффов**
1. На своём компьютере установите в VS Code расширения **Remote - SSH** и **Dev Containers**.
2. В пользовательских настройках VS Code (`settings.json`) задайте `"claudeCode.initialPermissionMode": "default"`. Тогда новые разговоры начинаются в режиме Manual.
3. Подключитесь: **Remote-SSH: Connect to Host** → `dev@адрес-сервера`.
4. **File → Open Folder** → папка проекта.
5. **Dev Containers: Reopen in Container**. Если в проекте несколько конфигураций, выберите `claude-box`.
6. Откройте панель Claude Code. Внизу у поля ввода должен стоять режим **Manual**: в нём каждая правка показывается диффом «было/стало» и ждёт вашего подтверждения. Если там Auto или Edit automatically, переключите на Manual. Выбранный вручную режим запоминается для следующих разговоров.

**Терминал**
- Открыть проект: `claude-box /путь/к/проекту` или `cd /путь/к/проекту && claude-box .`.
- Продолжить прошлую сессию проекта: `claude-box /путь/к/проекту --continue`.
- Несколько проектов можно открывать одновременно. Лимиты подписки у них общие.
- Работа без подтверждений: `claude-box /путь/к/проекту --dangerously-skip-permissions`. Только для доверенных проектов: в этом режиме агент может прочитать всё, что есть в контейнере, включая данные входа.

**Обслуживание**
- Подготовить новый проект для VS Code: `claude-box --vscode /путь/к/проекту`.
- Обновить Claude Code: `claude-box --update`, затем в VS Code **Dev Containers: Rebuild Container**.
- Свои настройки контейнера для терминала (например, лимит памяти) задаются в `~/claude-docker/docker-compose.override.yml`: установщик его не трогает. Файлы, которые генерирует установщик, при повторной установке перезаписываются, а ваши правки в них сохраняются рядом как `.bak-<дата>`.
- Выйти из аккаунта: `claude-box /путь/к/проекту auth logout`.
